# HEALINK DS18B20 integration

## Hardware

- DS18B20 DATA: BCM GPIO4
- DS18B20 VDD: 3.3 V
- DS18B20 GND: GND
- External DATA pull-up: 4.7 kOhm to 3.3 V

## Implementation

The driver performs a real single-device 1-Wire transaction directly on the
BCM2711 GPIO register block:

1. reset/presence
2. SKIP ROM
3. CONVERT T
4. conversion wait
5. reset/presence
6. SKIP ROM
7. READ SCRATCHPAD
8. nine-byte scratchpad read
9. CRC8 validation
10. signed 1/16 degree-C temperature decode

Short slot timing uses QNX `nanospin_ns()`. The long conversion interval uses
a sleep-capable `nanosleep()` helper, so the low-priority DS18B20 worker does
not spin the CPU during the conversion.

## HEALINK state behavior

Initialization:
- presence detected -> DS18B20 `ONLINE`, worker enabled
- no presence -> DS18B20 `OFFLINE`, worker remains disabled

After a successful initialization:
- valid CRC/range-checked measurement -> `VALID`
- reset/read/CRC/range failure -> existing HEALINK runtime `FAULT`
- missed timestamp -> existing HEALINK `STALE` handling

No fabricated temperature is ever published as valid.

## QNX/Raspberry Pi note

The existing `rpi_gpio` resource-manager helpers are retained for ordinary
GPIO operations. This DS18B20 driver does not use their command-line-backed
direction changes inside the 1-Wire timing slots because those slots require
microsecond-level direction/level control.
